# F12 implementation evidence

Subtitle search and download now run through `OnlineSubtitleJobs` and `AsyncOwnedJob`, with copied media/settings/item data and an owned worker. `App::OpenOnlineSubtitlesContextMenu` immediately presents the existing menu with a searching/downloading row. `App::PumpOnlineSubtitleJobs` applies completions on the UI thread. Changing media, provider, language, or opt-in invalidates the generation, cancels active requests, and discards stale completions. One bounded search-result cache survives menu reopening and successful downloads; failed searches have an explicit retry command.

Only the native updater fallback moved to these jobs. The existing packaged PowerShell launch path remains asynchronous. Native update checks and staging use copied configuration; changed configuration/private-mode state cancels pending results. Helper handoff posts `WM_CLOSE`, entering the normal persistence/worker drain. An `UpdateDownloadResult` owns its staging directory until successful helper launch, so discarded or failed handoffs clean temporary files.

`HttpRequestOptions::cancellation` enables a native asynchronous WinHTTP request. `HttpDetail::AsyncRequest` waits for send/header/read completions on the worker, closes the request on cancellation, and waits for `HANDLE_CLOSING` before releasing callback context or read buffers. Callers without a token retain the existing synchronous path. This distinction follows Microsoft's [WinHTTP concurrency rule](https://learn.microsoft.com/en-us/windows/win32/winhttp/concurrency-in-winhttp) and [request-cancellation/lifetime contract](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpclosehandle); concurrent closure of a synchronous request is prohibited.

Validation:

- `tests/updater/run_tests.ps1`: 36/36 passed in 281 ms. New checks cover cancellation before transport/storage and RAII cleanup of a discarded asynchronous staging result. Existing package streaming, hash, signature, architecture, rollback, and private-mode checks also passed.
- Seven `AsyncNetworkJobs` tests are registered through `TestOnlineSubtitles.h`: blocked-provider responsiveness and cache reuse; generation rejection despite a transport ignoring cancellation; stale-download storage suppression; cancellation interruption and exception recovery; language/opt-out cache invalidation; pre-cancelled service operations; and same-path media-generation/privacy invalidation. The final component gate includes these after the shared lifecycle runner integration.
- `run_http_async_probe.ps1` is an optional external HTTPS correctness probe, using the same `httpbingo.org` fixture as the earlier redirect checks. All five native probes passed: asynchronous normal response, redirect response, a 65,536-byte streamed file with no response-body accumulation, cancellation of an in-flight delayed response, and cancellation/temporary-file cleanup for the streamed-file path. Cancellation-to-worker-completion was 0.2301 ms and 0.582 ms in this run; these are cancellation observations, not throughput benchmarks. Raw results are in `http-async-results.csv`. The fixture is intentionally outside the deterministic regression gate.

Close integration is owned by F22: request cancellation, continue the close message pump while `AreNetworkJobsRunning()` is true, then `StopAndJoin()` after workers finish. Workers do not capture `App`, manipulate windows, or invoke application callbacks.
